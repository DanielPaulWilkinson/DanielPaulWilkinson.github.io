Recommendation

Produces a decisive software engineering recommendation from completed analysis, explaining why it wins, trade-offs, rejected alternatives, risks, implementation phases, confidence, and conditions that would change the decision.

State the answer first

Recommendation:

Then explain the decision in plain language.

Why this wins

Focus on the few engineering factors that actually decide the outcome.

Trade-offs

State what is gained and what is sacrificed.

Why alternatives lost

Discuss the strongest competitors only.

Risks

Include material risks and mitigations.

What would change the recommendation?

State concrete triggers.

Implementation path

Use the shortest sensible route:

Phase 1 — Validate

Phase 2 — Implement

Phase 3 — Harden

Phase 4 — Scale

Not every project needs every phase.

Confidence

High / Medium / Low with a brief explanation.
