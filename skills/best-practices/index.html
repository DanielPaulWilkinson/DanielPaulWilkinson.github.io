Answer: How should this be done well in a real software system?

Review

Architecture

Boundaries, coupling, cohesion, interfaces, failure isolation, extensibility.

Code quality

Maintainability, readability, conventions, dependency hygiene, technical debt.

Testing

Unit, integration, contract, end-to-end, testability, test pyramid/appropriate balance.

Security

Authentication, authorisation, secrets, validation, dependency risk, least privilege, threat exposure.

Delivery

CI/CD, versioning, migrations, feature flags, rollback, release safety.

Reliability

Timeouts, retries, idempotency, resilience, backups, recovery, failure modes.

Observability

Logs, metrics, traces, alerts, SLOs where relevant.

Performance

Measure before optimising; identify likely bottlenecks and capacity limits.

Operations

Ownership, upgrades, patching, support, runbooks, on-call burden.

Anti-patterns

Identify approaches that commonly create avoidable complexity or operational risk.

Context rule

Best practice is contextual. Do not recommend enterprise-grade machinery for a problem that does not require it.
