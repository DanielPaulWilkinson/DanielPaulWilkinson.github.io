Solution discovery

Maps genuinely different software engineering approaches to a goal before detailed evaluation, including simple, conventional, modern, build, buy, managed, open-source, hybrid, and defer/validate strategies where relevant.

Map the solution space before selecting a winner.

Consider

  • simplest viable design
  • conventional/established architecture
  • modern/emerging architecture
  • minimal-change option
  • build vs buy vs managed
  • open-source vs commercial
  • monolith/modular monolith/services where applicable
  • synchronous/asynchronous approaches where relevant
  • incremental migration vs replacement
  • hybrid architecture
  • defer/validate-first option

Do not create superficial variants merely to increase option count.

Software-engineering rule

Distinguish architectural decisions from implementation details. For example, changing vendors is usually not a fundamentally different architecture.
